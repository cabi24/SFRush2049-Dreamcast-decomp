Static evidence only. The original images and MAT3 checkout were read-only. No held-out function was compiled or used to tune configuration. Files in this lane are disposable analysis artifacts, not canonical decompilation source.

- **BodyVector identified:** file `0x16B00..0x16B5E` (94 bytes), VA `0x8C026B00`. `r4=src`, `r5=dst`, `r6=matrix`; no calls, stack, or pools. Every result reads a consecutive 12-byte matrix row, and the next row begins +12. `WorldVector` at `0x8C026B8C` uses the transposed addressing and is a useful wrong-candidate control. The neighborhood additionally has the matching U64WorldVector sign pattern. A confirmed caller at `0x8C024436` passes model+`0x2D4`, model+`0x208`, model+`0x2EC`.
- **Arithmetic detail:** each row starts with `src[2]*m[row][2]`, then FMAC for component 1, then FMAC for component 0. This is the reverse accumulation order of the textual MAT3 expression. The opcode sequence is known; exact rounding and FPSCR policy are not. `BodyVector-candidate.c` intentionally uses an unresolved DC_FMAC primitive. It is a translation scaffold, not an accepted E state.
- **Alias detail:** loads from source repeat for each row, after the prior destination store. If `src==dst`, later rows see updated earlier source elements. Do not hoist inputs or add `restrict`. The final destination store is at file `0x16B5C`, the delay slot of RTS at `0x16B5A`.
- **UpdateFrameTimer identified:** file `0x10A..0x176` (108 bytes), VA `0x8C01010A`. It reproduces the delta, paused countdown adjustment, running seconds update, five-frame clamp, and frame-seconds store sequence. Its pool dependencies are shared with the neighboring timer functions and should not be counted as exclusive data bytes.
- **Clock drift:** Dreamcast maintains counter `0x8C12253C` with callback `0x8C0100A4`, registered from InitializeTimer. MAT3 uses `sc.frameCount`. Preserve the DC counter and registration contract, not the GC scheduler structure.
- **GetWaveByIndex remains unlocated:** wave-instance base `0x8C15FA20`, stride 20, unsigned wave field +6, pointer +12, 64 entries are established from the loader, finder, and loops. A bounded examination of all aligned MOV.L PC-relative base/+field references in file `0..0x96000` found no standalone return of this field. The only base+6 literal is consumed at `0x8C065862` by a helper that branches into model setup. MAT3 has only one source caller, `decomp/src/NGC/ngcZoid.c:922`, a GC-renderer-specific use. A GC-added getter is plausible; absence is not proven. Keep this pilot slot visible as not found/possible drift.
