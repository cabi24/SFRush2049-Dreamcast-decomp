# Rendering, camera, HUD, resource and platform reference survey

## Decision

**Use MAT3 as the main readable semantic reference, not as a blanket platform implementation.** Of six target-backed cases, MAT3 is structurally closer in three (HUD teardown, viewport reset, synchronous resource loading); two shared kernels are ties (camera reset and control clearing); native Audio64 setup is neither. A seventh texture-upload candidate remains unresolved because its current C does not match the target. This is a deliberately small stratified sample, not a measured whole-game lineage percentage.

N64 is valuable native-platform triangulation: its camera-reset structure and offsets agree exactly with the Dreamcast model, and its different loader/control implementations expose assumptions that must not be imported. MAT3's better names and recovered types make it more usable even where both versions have the same algorithm. That usability advantage is distinct from evidence of target closeness.

## Scope and grounding

Read-only survey on 2026-10-27 of DC local workflow revision `8dee72f` (public source baseline `5fa10cd`), MAT3 at `1cfe284`, and N64 at `09da2f0`. Full public pins and repository path conventions are in the [index](README.md). No builds, game execution or game-source edits were performed during the survey.

DC evidence is **the stored Linux build**, not C text resemblance: `build/report.json` generated `2026-10-26T20:52:31`, paired with `build/linux-strict-receipt.json`. For the six target-backed rows the report marks the mapped function `exact`, `diff_bytes: 0`; each mapped interval is also contained within the strict receipt's credited text spans. Current source LF-normalized SHA-256 values agree with the report for all seven surveyed units. The strict receipt declares no comparison masks. This is a read-only review of existing build evidence, not a new independent compiler run.

Mapped size is not necessarily an entire isolated emission: `ZeroCamera` has a 90-byte mapped range but a 110-byte linked symbol, with surrounding literal dependencies. Do not quote 90 bytes as proof that every dependency belongs solely to that function. The source comments carrying addresses `0x800...` are MAT3 provenance, **not DC addresses**. Old `evidence/strict-integration-receipt.json` has stale raw source hashes for this checkout; it is not the evidence used here.

Abbreviations: **D** = DC `src/`; **M** = MAT3 `decomp/src/`; **N** = N64 `src/blob/`.

## Practical next decompilation use

1. Start shared camera/HUD/resource functions from MAT3's readable names/types, but retain a DC-specific delta list. The viewport constants, HUD overlay omission, and synchronous resource path above are already evidenced deltas.
2. Consult N64 by behavior and caller graph, not names. `particle_position_set` is camera reset; `audio_occlusion` is input clear; `audio_frame_sync` is resource loading; `car_shadow_render` is audio setup. Conversely `hud_speed_display.c` explicitly initializes object lists and `camera_reset.c` is not ZeroCamera. Search results on filenames alone are unsafe.
3. For native audio/render/input backends, target-first reconstruction is necessary. MAT3's retained DC-style identifiers (for example `DC_SendBlit` in GC source) alone do not prove a native DC implementation.
4. The unresolved upload row should be validated against complete target decoding/call contracts before selecting a foreign analogue. No additional builds are required to reach this survey's present conclusion.

## Limits

Both repositories are reconstructed references, not independent pristine original sources. Existing DC C explicitly derives names/behavior from MAT3, and N64 comments sometimes cite MAT3; therefore text identity and comments alone are circular. Stored exact DC build evidence breaks the circularity for the six mapped behavior comparisons, but it does not recover original authorship or prove historical lineage. No fresh N64 or MAT3 matching build was run; their code is used as available reference evidence. Negative counterpart searches mean **not located**, not proved absent. The low-confidence renderer candidate is excluded from the six-row result tally.
